# 記事管理ルール

このディレクトリには「保育士転職」ブログの記事を1本1ファイルで管理します。
役割(担当者)ごとにファイルを分けるのではなく、**記事ごとにファイルを分け、
front matter(冒頭のメタデータ)で担当者・進捗を管理**します。

## ファイルの探し方

- `記事ID-スラッグ.md`(例: `C-site-comparison-ranking.md`)
- どの記事がどのキーワードに対応するかは各ファイルの `keywords` を参照。
  全体の一覧は `../kw_project_plan.xlsx` の「記事管理」シートも参照。

## front matter の項目

| 項目 | 内容 |
|---|---|
| `id` | 記事ID(キーワード選定シートと対応) |
| `title` | 記事タイトル案 |
| `keywords` | 統合対象キーワード一覧 |
| `priority` | 優先度(最高/高/中) |
| `phase` | Tier1 / Tier2 / ピラー |
| `status` | 進捗ステータス(下記参照) |
| `writer` | 担当ライター名(未定なら空欄) |
| `reviewer` | 担当校正者名(未定なら空欄) |
| `write_period` / `review_period` | 逆算スケジュール上の目安期間 |
| `notes` | 執筆時の注意点・統合の背景 |

## ステータスの値

`未着手` → `執筆中` → `校正待ち` → `校正済み` → `公開済み`

担当者は自分が着手・完了するタイミングで `status` と `writer`/`reviewer` を
更新してください。誰が何を持っているかは各ファイルを開くか、下記コマンドで
一覧できます。

```bash
grep -H "^status:\|^writer:\|^title:" articles/*.md
```

## 進め方

1. ライターは `status: 未着手` かつ自分の専門に近いものを選び、`writer` を
   自分の名前にして `status: 執筆中` に変更してから本文を書く。
2. 書き終えたら `status: 校正待ち` にする。
3. 校正者は `校正待ち` のものをレビューし、`reviewer` を記入して
   `校正済み` にする。
4. 公開担当が実際のブログに反映したら `公開済み` にする。
